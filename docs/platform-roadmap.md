# Следующий этап: анализ команды и матчей

План развития и статус реализации. Первый рабочий цикл описан в разделе «Реализовано» ниже; инфраструктурные и событийные этапы остаются следующими.

## Продуктовая цель

Дать аналитику полный рабочий цикл: выбрать свою команду → разобрать матч → проверить вклад игроков → сравнить периоды → сохранить вывод и вернуться к нему после следующей игры. Recruitment остаётся одним из сценариев наряду с анализом собственной команды, подготовкой к сопернику и развитием игроков.

Идея Moneyball полезна как принцип проверяемых решений при ограниченных ресурсах. Низкая цена и высокий рейтинг сами по себе не доказывают недооценённость. Нужно учитывать игровую роль, контекст команды, качество наблюдений и последующий результат решения.

## Что ограничивает проект сейчас

- API обслуживает сезонные агрегаты и нормализованное файловое ядро «команда — матч — участие игрока». Общая база PostgreSQL и многопользовательская работа ещё не внедрены.
- На момент аудита: 185 связанных составов, 254 состава без метаданных матча, один сохранённый 404. Подтверждённая выборка текущего сезона отсутствует.
- Сумма статистики игроков не является автоматически официальной командной статистикой: часть игроков или метрик может отсутствовать.
- Heatmap — не последовательность передач, прессинг-действий или трекинг всех игроков. По ней нельзя восстановить отсутствующие события.

## Последовательность реализации

| Этап | Результат для пользователя | Реализация | Условие готовности |
|---|---|---|---|
| 1. Проверенная история матчей | Видно, какие матчи и показатели действительно доступны | Догрузить метаданные матчей и составы; хранить статусы загрузки и покрытие по сезону/матчу | Каждый показанный матч имеет явные competition, season, event ID; пропуски перечислены, дубликатов нет |
| 2. Общая база данных | Один и тот же матч/игрок одинаково определяется во всех разделах | PostgreSQL: competitions, seasons, teams, players, matches, appearances, player_match_stats, source_snapshots, sync_runs. Отдельно IDs провайдеров, время наблюдения и версии расчётов. Raw snapshots сохраняются до нормализации | Импорт повторяем без дубликатов; показатели сверяются с исходными ответами; исправление источника оставляет историю |
| 3. Центр матчей | Открыть матч, увидеть результат, составы, минуты и доступные показатели игроков | `/api/matches`, `/api/matches/[id]`, фильтры по команде/сезону; отдельные поля покрытия метрик | Один выбранный клуб и доступный сезон проходят полный сценарий; результат матча и состав связаны с источником |
| 4. Страница команды | Сравнить последние 5 доступных матчей с предыдущими 5, увидеть участие игроков и изменения показателей | `/api/teams/[id]/matches`, `/api/players/[id]/matches`; временные ряды с датами, соперником и минутами | Графики используют матчевые значения, не деление сезонной суммы; отсутствующие матчи отмечены, подборка не названа полной |
| 5. Разбор и развитие | Аналитик сохраняет выводы по игре и отслеживает конкретных игроков | Отчёты, заметки, ссылка на исходные показатели и период; индивидуальные цели и сравнение до/после | Рекомендация связана с наблюдаемыми данными, автором и датой; можно проверить её после новых матчей |
| 6. Событийная аналитика | Карты ударов, передачи между игроками, разбор продвижения мяча и соперника | Отдельный адаптер event data; player/team/time/coordinates, спецификация координат, направление атаки и покрытие | Подтверждены реальные события для целевой лиги. Карты не строятся по вымышленным точкам. Метрики проверены на известных матчах |

Не добавлять сразу десятки экранов. Первый законченный выпуск — **команда → список матчей → конкретный матч → показатели игрока в этом матче**. Достаточно одной лиги, одного доступного сезона и одного клуба для полноценной проверки сценария.

## Как выбирать метрики

Сначала показывать то, что есть в источнике: счёт, минуты, голы, удары, передачи, единоборства, xG/xA при фактическом наличии. У каждой агрегированной метрики — число покрытых матчей и правило пропусков. Не сравнивать неизвестное с нулём. Не выводить командное владение, PPDA, xT или сети передач из отсутствующих событий.

Для моделей позже нужны отдельные определения, версии, историческая проверка без использования будущих данных и сравнение с простым базовым методом. Визуальная сложность и количество рейтингов не являются критерием качества платформы.

## Данные для разработки событийного модуля

Открытые данные StatsBomb/Hudl дают реальные соревнования, матчи, составы и события для выбранных покрываемых турниров. Это подходящий отдельный набор для разработки и проверки адаптера событий. Он не подменяет данные Узбекистана или Казахстана и не гарантирует их покрытие. Требования источника к использованию и атрибуции проверяются перед использованием в продукте.

## Критерий пользы

Аналитик должен суметь подготовить проверяемый разбор одного матча и найти изменение в игре конкретного футболиста, затем объяснить тренеру, на каких наблюдениях основан вывод. Это первый шаг от каталога трансферных кандидатов к рабочей football intelligence platform.

## Реализовано 2 октября 2026

Первый сквозной сценарий: команда → доступные матчи → участие игрока → динамика → сохранённый вывод → ручная отметка результата проверки. Добавлены файловое нормализованное матчевое ядро, API `/api/analysis`, покрытие частичных наблюдений и парные знаменатели процентов. Скаутский индекс и схожесть сохранены. Профиль показывает исходные значения и реальное среднее по позиции на общей шкале без дублирующего переключения процентилей.

Рабочее пространство команды разделено на обзор, матчи, состав и выводы. Отрезки по 5/10 доступных матчей сравниваются по результатам источника. Из матча открывается профиль игрока, из его истории — нужный матч; из состава — поиск усиления с позицией, периодом и названием команды. Сохранённые выводы можно редактировать без изменения исходного основания, затем отмечать результат проверки.

Следующие этапы остаются открытыми: догрузка текущего сезона, PostgreSQL с миграциями и историей снимков, аккаунты и общие отчёты. Событийная аналитика зависит от получения реальных событий. Текущий выпуск не заявляет, что эти этапы выполнены.


## Открытые части глобального шага

Этот выпуск — частичная реализация всего этапа, а не его полное завершение.

- Центр матчей показывает счёт, обе стороны, минуты, доступные показатели и отсутствие состава/значений. Сводное покрытие каждой метрики по составу ещё не показано.
- Состав команды содержит участие и минуты каждого игрока. Изменения результатов доступны по отрезкам. Отдельной карты глубины по подтверждённым точным позициям и долей распределения минут пока нет.
- Динамика игрока построена по отдельным матчам с пропусками.
- Recruitment получает выбранную позицию, период и название команды. Зафиксированная потребность команды ещё не связана с результатами подбора и решением о конкретном кандидате.
- Выводы содержат основания, решение и критерий проверки; результат отмечается вручную. Отдельного сравнения новых матчей с исходным периодом конкретного решения и уведомления о сроке проверки ещё нет.
