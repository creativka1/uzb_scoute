# UzStat Talent Tracker

Скаутинг и сравнение игроков лиг Узбекистана и Казахстана на Next.js 15, React 19 и TypeScript. Источник футбольных данных — сохранённые ответы SofaScore. Интерфейс поддерживает русский и узбекский языки.

## Запуск и проверка

Нужны Node.js 22 и Python 3.11+.

```bash
npm ci
npm run dev
# http://localhost:3000
npm test
npm run typecheck
npm run build
```

Тесты работают без сети и ключей. HTTP-ответы в тестах синхронизации — изолированные синтетические fixtures; в рабочие данные они не записываются.

## Контракт данных

- Отсутствующее значение — `null`, в интерфейсе — `—`. Реальный ноль сохраняется. Возраст, рост, стоимость, гражданство, клуб и позиция не заполняются придуманными значениями.
- Статистика относится только к матчам с явным `eventId`, соревнованием, сезоном и подтверждённым составом. Игрок и исторический клуб связываются через сторону матча; `player.teamId` может отражать более поздний переход.
- Если метрика отсутствует хотя бы в одном сыгранном матче выборки, полный итог этой метрики — `null`. Известная часть остаётся в `observedTotals`, число наблюдений — в `metricCoverage`. Сырые ответы сохранены.
- `current`, `previous`, `two` означают конкретные сезоны из метаданных источника. `latest` выбирает один доступный сезон для всей лиги; индивидуальной подстановки прошлого сезона нет.
- Покрытие сезона отмечается как неполное, пока не пройдены все страницы и не получены составы всех завершённых матчей. Даже полное покрытие матчей не гарантирует наличия каждой метрики.
- Точная позиция берётся только из однозначного `player.positionsDetailed`, согласующегося с широкой позицией источника. Расчёты по порядку состава, схеме и heatmap сохраняются как неподтверждённые кандидаты, а не футбольные факты.
- Процентили сравниваются внутри одной лиги, сезона и широкой позиции. Для каждой метрики нужен минимум из трёх игроков с 450+ минутами. В интерфейсе исходный процентиль отделён от рассчитанного рейтинга с поправкой на минуты.
- Бюджетные замены требуют известных стоимостей и строго меньшей стоимости кандидата. Сохранённые кандидаты хранятся в этом браузере независимо от фильтров; очищение фильтров их не удаляет. Повреждённое локальное сохранение не перезаписывается автоматически.

## Поток данных

1. `data/cache/seasons`, `lineups`, `players`, `heatmaps` — ответы источника.
2. `scripts/data_integrity.py` — проверка связей и детерминированная сборка `data/superliga_stats.json` и `data/audits/data_integrity.json`.
3. `scripts/build_detailed_positions.py` — подтверждённые профильные позиции и отдельно кандидаты.
4. `app/api/players/route.ts` — выбор периода, расчёт метрик и ролевых процентилей.
5. `app/page.tsx`, `lib/recruitment.ts`, `types/players.ts` — интерфейс, подбор и общий nullable-контракт.

`GET /api/players?league=UZB&season=latest` возвращает массив игроков и заголовок `X-Data-Metadata` с выбранным периодом и покрытием. Допустимы `league=UZB|KAZ|all`, `season=latest|current|previous|two`. Некорректный фильтр даёт 400; отсутствующий набор данных — 503; повреждённый — 500. Ошибки не маскируются успешным пустым массивом.

Пересборка без обращения к провайдеру:

```bash
python scripts/data_integrity.py
python scripts/build_detailed_positions.py
```

## Обновление источников

Для сетевых скриптов нужен `pip install curl_cffi`.

- **Sync verified match statistics** — ручной workflow для обеих лиг и двух сезонов. Требует существующий secret `RAPIDAPI_KEY`. Проходит страницы до `hasNextPage=false`, проверяет сезон ответа, считает реальные HTTP-попытки, сохраняет промежуточный кэш. Параметр `max_requests` ограничивает расход квоты, включая retries; значение по умолчанию — 1500. Это лимит, а не гарантированное число запросов для полного обновления.
- **Refresh player profiles** — ежедневное обновление профилей через публичный endpoint. Кэш с известной датой используется 24 часа. Ошибки доступа прерывают серию после десяти неудач и отмечают workflow как failed; старый ответ при сетевой ошибке сохраняется.
- **Sync SofaScore Heatmaps** — существующая ежедневная небольшая серия: максимум 12 HTTP-попыток. Пустые ответы временно кэшируются на 7 дней, ошибки — на час. 429 не считается успешной загрузкой.
- Каждый workflow сам пересобирает нужные производные файлы: push через `GITHUB_TOKEN` не используется как механизм запуска следующего workflow.
- Записывающие workflow выполняются последовательно. Ошибка сохраняет доступные промежуточные данные и отчёт, но не превращает неполный запуск в успешный.

## Ограничения восстановленного кэша

На момент исправления проверены 440 файлов составов: 185 связаны с описаниями матчей (99 UZB, 86 KAZ), 254 пока не имеют метаданных матча, один содержит ответ 404. Все исходные файлы сохранены. В проверенной выборке есть статистика 2025 года для 722 записей игроков; подтверждённой выборки 2026 года пока нет. Реестр содержит 895 записей «лига + игрок», включая игроков без проверенной статистики.

Поэтому выбор 2026 сейчас честно возвращает пустой список, а `latest` показывает явно подписанный 2025 год с предупреждением о неполном покрытии. Для восстановления остальных матчей нужно запустить исправленную синхронизацию и получить недостающие ответы источника. Полнота и точные позиции не появятся только от пересчёта старых файлов.

## Интерфейс и развитие платформы

Основные разделы: «Игроки», «Поиск под задачу» и «Сохранённые». В профиле обзор отделён от полной статистики; числовые значения отделены от положения в группе сравнения. Размер выборки, процентили и методика доступны в раскрываемом пояснении. Необозначенные P/N больше не используются.
